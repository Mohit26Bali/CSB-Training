TEST CASES WITH FULL REQUESTS AND EXPECTED JSON
================================================
10 test cases that together cover: authentication, role-based access, course management,
validation, enrollment request, every business rule, approval, rejection, capacity.

Base URL : http://localhost:8080
Run each case in ORDER. Later cases depend on earlier ones.

HOW TO RUN
  Postman : choose the method, paste the URL, Authorization tab -> Basic Auth
            (type the username and password shown), for POST/PUT set Body -> raw -> JSON
            and paste the JSON shown.
  curl    : each case also has a curl command (run it in Git Bash, not PowerShell).

STARTING STATE (sample data, no earlier test enrollments)
  Course 1  Java Basics        capacity 2  active    2 approved  -> FULL
  Course 2  Spring Boot        capacity 3  active
  Course 6  SQL Fundamentals   capacity 3  active
  Course 7  Cyber Awareness    capacity 1  active
  Course 8  Old Mainframe      capacity 4  INACTIVE
  Enrollment 5  employee3 -> Cyber Awareness  PENDING
  Enrollment 6  employee4 -> Cyber Awareness  PENDING

  To get this state, in MySQL:   DELETE FROM enrollments;
  then re-run the "enrollments" INSERT statements from sample-data.sql.
  Check the ids with CASE 0 below.

Values that change on your machine (ids, timestamps) are marked  <...>  in the responses.

CASE 2: Role-based authorization (employee blocked from admin API)
----------------------------------------------------------------------
Feature : employees must not access admin APIs
POST http://localhost:8080/api/admin/courses
Login: employee1 / employee123
Header: Content-Type: application/json
Body:
{
  "title": "Hacked Course",
  "description": "An employee should not be able to create this",
  "category": "Test",
  "capacity": 10
}

curl -u employee1:employee123 -X POST http://localhost:8080/api/admin/courses \
  -H "Content-Type: application/json" \
  -d '{"title":"Hacked Course","description":"An employee should not be able to create this","category":"Test","capacity":10}'

Expected: HTTP 403 Forbidden (no JSON body; nothing is created)

CASE 3: Admin creates a course
----------------------------------------------------------------------
Feature : admin manages courses
POST http://localhost:8080/api/admin/courses
Login: admin / admin123
Header: Content-Type: application/json
Body:
{
  "title": "Docker Essentials",
  "description": "Containers for beginners",
  "category": "DevOps",
  "capacity": 5
}

  -H "Content-Type: application/json" \

Expected 201 Created:
{
  "id": <new id>,
  "title": "Docker Essentials",
  "description": "Containers for beginners",
  "category": "DevOps",
  "capacity": 5,
  "active": true,
  "approvedCount": 0
}

Then update it (replace <new id> with the id returned above):
PUT http://localhost:8080/api/admin/courses/<new id>
Login: admin / admin123
Body:
{
  "title": "Docker Essentials",
  "description": "Updated: containers and images",
  "category": "DevOps",
  "capacity": 8,
  "active": true
}
Expected 200 with "capacity": 8 and the new description.

CASE 6: Business rule - no duplicate enrollment
----------------------------------------------------------------------
Rule    : a user cannot enroll in the same course twice
POST http://localhost:8080/api/enrollments
Login: employee1 / employee123
Header: Content-Type: application/json
Body:
{
  "courseId": 6
}
(exactly the same request as CASE 5)

curl -u employee1:employee123 -X POST http://localhost:8080/api/enrollments \
  -H "Content-Type: application/json" \
  -d '{"courseId":6}'

Expected 409 Conflict:
{
  "status": 409,
  "error": "Conflict",
  "message": "You have already requested this course",
  "timestamp": "<timestamp>"
}
