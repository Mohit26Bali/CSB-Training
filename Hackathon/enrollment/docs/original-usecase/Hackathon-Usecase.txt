13. Online Course Enrollment and Approval System
Business Problem: Employees want to enroll in internal training courses while administrators need to control course capacity and enrollment.
Users / Roles: EMPLOYEE, ADMIN
Core Features:
•	Users can browse available courses.
•	Employee submits an enrollment request.
•	Employee views their enrolled/requested courses.
•	Admin creates and manages courses.
•	Admin approves or rejects enrollment requests.
•	Course capacity must be respected.
Business Rules / Validation: A user cannot enroll in the same course twice; enrollment cannot exceed course capacity; inactive courses cannot accept enrollment.
Optional Bonus: Course search, category filtering, enrollment count dashboard.
7-Hour Scope Guidance: Teams should implement authentication, the core business workflow, JPA persistence, role-based authorization, REST APIs. Advanced features should only be attempted after the end-to-end flow works.



Common Technology and Architecture Requirements:

- Spring Core: Use IoC, dependency injection, stereotypes such as @Service and @Repository, and constructor injection. Implementation is to be done in Eclipse. 
- Spring Boot: Use Spring Boot, configuration through application.properties/yml, auto-configuration and an embedded server.
- Spring MVC / REST: Use @RestController, request mappings, request/response DTOs, path variables, request bodies and appropriate HTTP methods/status codes.
-Spring Data JPA: Use entities, relationships, JpaRepository and derived/custom queries where needed.
-Spring Security: Implement login/authentication, password encoding and role-based authorization. Employees/customers must not access admin APIs.
- Database: Use MySQL(password is "mohit123") with primary keys, foreign keys, unique constraints and suitable validation.
- Validation: Validate both input data and business rules at the backend. Display meaningful errors in React.
- Architecture: Postman ->  REST Controller → Service → Repository → Database.
- Deliverables: Source code, database setup, README(ignore for now), API documentation(not needed for now), sample credentials and a working demonstration.
- For any data related processing Streams must be used.
