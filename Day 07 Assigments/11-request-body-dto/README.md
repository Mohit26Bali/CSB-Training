# 11. Request Body + DTO

**Concept:** Spring MVC. `POST /api/employees` receives a JSON **`EmployeeRequest`** (`name`, `email`, `department`) via **`@RequestBody`**, stores it in MySQL, and returns an **`EmployeeResponse`**. The optional extension adds a nested **`AddressDto`**.

Request problems become clear JSON errors from a `@RestControllerAdvice`:
- missing data → **400 with per-field errors**
- malformed JSON → **400**
- duplicate e-mail → **409**
- wrong content type → **415**

## Tech

Java 17 · Maven · **Spring Boot 3.5.6** (starter-web, starter-validation, starter-jdbc) · MySQL 8

**Database:** shared Day 07 database `Day_007_Assigments`, table **`a11_employees`**. The e-mail column is `UNIQUE`.

Data flows through three shapes:

```text
JSON  --Jackson-->  EmployeeRequest (+AddressDto)  --service-->  Employee (flat)  --JdbcTemplate-->  a11_employees
JSON  <--Jackson--  EmployeeResponse (+AddressDto) <--service--  Employee         <--RowMapper----   a11_employees
```

## How to run

1. Run `src/main/resources/schema.sql` in MySQL. It recreates only `a11_employees`; re-run it to reset the data.
2. **Eclipse:** **File → Import → Maven → Existing Maven Projects**, select `11-request-body-dto`, then right-click `RequestBodyDtoApplication` → **Run As → Java Application**.
3. **POST with Postman:** method `POST`, URL `http://localhost:8080/api/employees`, **Body → raw → JSON**:

   ```json
   {
     "name": "Asha Rao",
     "email": "asha.rao@company.com",
     "department": "Finance",
     "address": { "street": "12 MG Road", "city": "Bengaluru", "state": "Karnataka", "pincode": "560001" }
   }
   ```

   **Or with curl in cmd:**

   ```text
   curl -i -X POST -H "Content-Type: application/json" -d "{\"name\":\"Mohit Sharma\",\"email\":\"mohit@company.com\",\"department\":\"Engineering\"}" http://localhost:8080/api/employees
   ```

4. Read a saved employee back with `GET http://localhost:8080/api/employees/1`.

## Failure / edge-case evidence

### Missing data: valid JSON, but `@Valid` rejects it (400 + field errors)

| Request body | Status | Response |
|---|---|---|
| `{}` | **400** | `"fieldErrors":{"name":"name is required","department":"department is required","email":"email is required"}` |
| `{"name":"Kiran","department":"Sales"}` | **400** | `"fieldErrors":{"email":"email is required"}` |
| `{"name":"   ","email":"not-an-email","department":"Sales"}` | **400** | `"fieldErrors":{"email":"email must be a valid e-mail address","name":"name is required"}` |
| `{..., "address":{"street":"1 Park St","pincode":"12AB"}}` | **400** | `"fieldErrors":{"address.pincode":"address.pincode must be exactly 6 digits","address.city":"address.city is required"}` |
| `{"name":"Mohit Duplicate","email":"MOHIT@company.com",...}` | **409** | `"message":"An employee with this email already exists"` |

The full body of the first case:

```json
{"timestamp":"2026-10-11T11:46:19","status":400,"error":"Bad Request","message":"Validation failed","fieldErrors":{"name":"name is required","department":"department is required","email":"email is required"}}
```

What these show:
- **All** problems are reported at once, not just the first.
- A whitespace-only name fails `@NotBlank`.
- Nested errors are reported as `address.xxx`, because `@Valid` on the `address` field cascades into `AddressDto`.
- The duplicate was caught **after** lower-casing `MOHIT@company.com`, by the table's `UNIQUE` key; `DuplicateKeyException` is mapped to 409.
- The controller method never runs for invalid input, and nothing is inserted.

### Malformed JSON: Jackson cannot read it (400)

| Request body | Status | `message` |
|---|---|---|
| `{"name":"Kiran","email":"kiran@company.com","department":"Sales"` | **400** | `Malformed JSON request: Unexpected end-of-input: expected close marker for Object` |
| `{'name':'Kiran'}` | **400** | `Malformed JSON request: Unexpected character (''' (code 39)): was expecting double-quote to start field name` |
| `{"name":"Kiran" "email":"kiran@company.com"}` | **400** | `Malformed JSON request: Unexpected character ('"' (code 34)): was expecting comma to separate Object entries` |
| `{..., "department":["Sales","HR"]}` | **400** | ``Malformed JSON request: Cannot deserialize value of type `java.lang.String` from Array value (token `JsonToken.START_ARRAY`)`` |
| `{..., "address":"Bengaluru"}` | **400** | ``Malformed JSON request: Cannot construct instance of `com.company.boot.dto.AddressDto` (although at least one Creator exists): no String-argument constructor/factory method to deserialize from String value ('Bengaluru')`` |
| *(empty body)* | **400** | `Request body is missing` |
| `name=Kiran&email=...` with `Content-Type: application/x-www-form-urlencoded` | **415** | `Content-Type 'application/x-www-form-urlencoded;charset=UTF-8' is not supported; send application/json` |

These fail **before** validation. Jackson throws `HttpMessageNotReadableException`, and the advice turns it into a 400.

### Jackson's lenient defaults: these were *accepted*, which is worth knowing

| Request body | Status | What happened |
|---|---|---|
| `{"name":"Ravi","email":"ravi@company.com","department":"HR","salary":90000,"role":"admin"}` | **201** | `salary` and `role` were **silently ignored**. They are not in the DTO, so a client cannot inject fields the API does not define. |
| `{"name":123,"email":"num@company.com","department":"IT"}` | **201** | the number `123` was **coerced** to the String `"123"` (row 4 above) |

**Strict mode, without any Java change.** Started with `--spring.jackson.deserialization.fail-on-unknown-properties=true`, the same unknown-field request gives:

```json
{"timestamp":"2026-10-11T11:46:30","status":400,"error":"Bad Request","message":"Malformed JSON request: Unrecognized field \"salary\" (class com.company.boot.dto.EmployeeRequest), not marked as ignorable (4 known properties: \"department\", \"name\", \"email\", \"address\"])"}
```

Spring Boot sets this flag to `false` by default. Jackson on its own would reject unknown fields.

## Explanation

**`@RequestBody`** tells Spring MVC to read the **HTTP request body** and convert it into the parameter's type.
- The converter is picked by the `Content-Type` header: `application/json` uses Jackson's `MappingJackson2HttpMessageConverter`. Any other type gives 415.
- A missing or unreadable body gives 400.
- Adding **`@Valid`** runs Bean Validation on the result. When it fails, the method is not called, and `MethodArgumentNotValidException` is raised (400).

**DTO (Data Transfer Object):** a simple class whose only job is to carry data across the API boundary. Separate request/response DTOs instead of exposing the table model mean:
- **The API contract is independent of the database.** The address is nested in JSON but flat in MySQL, and either can change without breaking the other.
- **The client controls only what it should.** It cannot send `id`, `createdAt` or unknown fields like `salary`.
- **The server returns only what it should.** It adds `id`, `employeeCode` and `createdAt`, and would never leak internal columns.
- **Input rules live in one place.** `@NotBlank`, `@Email` and `@Pattern` sit on the request DTO.

**Jackson mapping:**
- **JSON → Java (deserialisation):** Jackson calls the **no-arg constructor**, then the **setter matching each JSON property name** (`"email"` → `setEmail`). A nested JSON object (`"address": {...}`) is mapped recursively into the field's type (`AddressDto`). A type mismatch, such as an array for a `String` or a string for an object, gives an error.
- **Java → JSON (serialisation):** every **getter** becomes a property (`getEmployeeCode()` → `"employeeCode"`). Nested objects become nested JSON, `null` becomes `null`, and `LocalDateTime` becomes an ISO string. Annotations adjust this: `ErrorResponse` uses `@JsonInclude(NON_NULL)` to drop an empty `fieldErrors`, and `@JsonPropertyOrder` to fix the field order.
- **Spring Boot's defaults** ignore unknown properties and coerce scalars. The `spring.jackson.*` properties change this, as the strict-mode run shows.

**`@RestControllerAdvice`** (`GlobalExceptionHandler`) centralises error handling for all controllers, so every failure has the same JSON shape.
